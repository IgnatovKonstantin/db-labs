#Лабораторная работа №8 (дополнительная) - Конкурентный доступ и транзакционная целостность
  
##Цель 
Научиться выявлять ошибки конкурентного доступа и обеспечивать корректность бизнес-операций при одновременном выполнении транзакций. 
  
##Содержание работы 
Необходимо выбрать одну бизнес-операцию своей предметной области, для которой 
возможен конфликт при конкурентном выполнении. 
  
###Например: 
- бронирование последнего доступного места; 
- списание средств; 
- резервирование товара; 
- назначение исполнителя; 
- выдача ограниченного ресурса; 
- изменение лимита; 
- регистрация на мероприятие с ограниченным числом участников. 
  
###Далее необходимо: 
1. Реализовать наивный вариант операции, корректный при последовательном 
выполнении. 
2. В двух или более параллельных сессиях продемонстрировать нарушение 
бизнес-инварианта.
####Например: 
available = 1 
T1: проверяет available > 0 
T2: проверяет available > 0 
T1: выполняет бронирование 
T2: выполняет бронирование 
  
Результат: создано две брони при одном доступном месте
  
3. Определить: 
- какие транзакции участвуют; 
- какой бизнес-инвариант нарушается; 
- почему обычной транзакции недостаточно. 
4. Реализовать не менее двух способов исправления из следующих: 
- SELECT ... FOR UPDATE; 
- FOR NO KEY UPDATE / FOR SHARE; 
- атомарный UPDATE ... WHERE ... RETURNING; 
- SERIALIZABLE; 
- optimistic concurrency control; 
- advisory locks; 
- ограничения БД (UNIQUE, EXCLUDE и др.), если применимо. 
5. Провести конкурентный тест исправленных вариантов и доказать, что бизнес-инвариант больше не нарушается. 
6. Для одного из вариантов искусственно создать deadlock: 
- показать участвующие транзакции; 
- зафиксировать реакцию PostgreSQL; 
- изменить порядок блокировок так, чтобы deadlock исчез. 
7. Сравнить разработанные решения по: 
- корректности; 
- сложности; 
- степени блокировки данных; 
- потенциальной пропускной способности.
  
##Отчетные материалы 
- описание бизнес-инварианта; 
- SQL исходного некорректного решения; 
- сценарий конкурентного выполнения; 
- результат, демонстрирующий race condition; 
- минимум два варианта исправления; 
- сценарии проверки исправленных вариантов; 
- сценарий deadlock и способ его устранения; 
- сравнительная таблица решений.
